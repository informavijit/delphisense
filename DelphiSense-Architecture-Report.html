Executive Summary

DelphiSense is a high-performance, lightweight code review and static analysis extension for Visual Studio Code, optimized specifically for Embarcadero Delphi and Object Pascal projects (`.pas`, `.dpr`, `.dpk`, `.pp`, `.inc`).

Traditional language servers for Pascal frequently require matching compiler binaries, configured library paths, and complex project setup. DelphiSense bypasses these friction points through a resilient, single-pass line-oriented scanner that extracts structural code metrics and flags vulnerabilities across any version of Delphi or FreePascal.

  • Zero Language Server Overhead: Requires no Delphi IDE install, `.dproj` parsing, or external toolchains.
  • Decoupled Core Engine: Built with standard TypeScript (`src/engine/`) without VS Code runtime dependencies, enabling future CLI or CI/CD integration.
  • String & Comment Neutralization: Algorithmic blanking guarantees zero false-positive matches inside string literals or multiline comments.
  • Professional HTML Reports: Generates self-contained, offline-safe code review reports organized into 8 distinct analytical categories with dynamic Quality Scoring.

Main Report Categories & Key Sections

DelphiSense categorizes static analysis findings and code review insights into 8 specialized report sections to ensure comprehensive visibility across all developer and architectural concerns:

1
Status Report
Always generated first. Details analysis target parameters, line counts, scanned files, execution time (ms), disabled rules, and custom rule configurations.
Target Metadata Rule Settings Execution Stats
2
General & Strong Warnings
Highlights critical runtime showstoppers, potential bugs, uninitialized variables, empty exception handlers, unhandled destructor calls, and dead code following Exit/raise.
emptyExceptFinally deadCodeAfterExit unassignedVariable
3
Optimization Report
Identifies performance enhancement opportunities, such as string concatenation inside loops (recommending TStringBuilder) or getter/setter method inline candidates.
stringConcatInLoop inlineDirectives LoopAllocations
4
Code Reduction Report
Pinpoints dead, redundant, or unused code for refactoring. Covers unused variables, redundant boolean comparisons (e.g. if X = True), and unused parameters.
unusedVariable redundantBoolean unusedParameter
5
Uses Dependency Report
Analyzes unit uses clauses across interface and implementation sections. Identifies unneeded unit imports and units eligible to shift to implementation.
unusedUses usesShiftToImpl DependencyCycles
6
Metrics & Complexity
Measures structural code metrics per routine, including Lines of Code (LOC), block nesting depth (deepNesting), and Cyclomatic Decision Points (DP).
longMethod deepNesting CyclomaticDP
7
Reference & Cross-Reference
Maps out project identifiers, showing where specific variables, methods, or classes are declared and referenced across units, plus detecting local variable shadowing.
SymbolMapping shadowedVariable CrossUnitRefs
8
Class & Control Reports
Documents object-oriented design structures, verifying Pascal naming conventions (T/I/F prefixes), override keywords on virtual methods, and field access boundaries.
pascalNaming missingOverride ClassHierarchy

Code Review Rules Elaboration & Catalog

DelphiSense evaluates code using a two-tier rule engine: Built-in Rules (written in TypeScript with AST-neutral structural inspection) and Custom Workspace Rules (declarative JSON-defined regex patterns). Every rule implements the standardized Rule contract and generates granular Finding instances.

unusedUses Unused Uses Clause Entry
Hint
CategoryUses Report
Source Filesrc/engine/builtinRules/unusedUses.ts
Config Disable Key"unusedUses" in delphisense.rules.disabled

Description & Objective: Scans unit imports in interface, implementation, and program level uses clauses. Flags any imported unit whose short name is never referenced anywhere else in the unit source file. Helps clean up unit interface bloat, reduce binary unit linking, and prevent symbol ambiguity.

Detection Algorithm: Extracts short unit names (e.g. System.SysUtils → SysUtils). Constructs a global word-boundary regular expression \bSysUtils\b and executes it against the clean unit text. If total occurrences $\le 1$ (meaning it only appears once in the uses clause itself), it generates a Hint finding.

⚠️ Anti-Pattern (Unused Unit)
unit SampleUnit;

interface

uses
  System.SysUtils, System.Classes, Vcl.Dialogs; // Vcl.Dialogs is never referenced!

type
  TMyClass = class(TPersistent);
✅ Recommended Compliant Code
unit SampleUnit;

interface

uses
  System.SysUtils, System.Classes; // Removed unused Vcl.Dialogs

type
  TMyClass = class(TPersistent);
longMethod Excessive Method Body Length
Warning
CategoryMetrics & Complexity
Source Filesrc/engine/builtinRules/longMethod.ts
Config Settingdelphisense.longMethod.maxLines (default: 60)

Description & Objective: Flags procedures, functions, constructors, or destructors whose body line count exceeds the maximum recommended threshold. Promotes the Single Responsibility Principle (SRP) and improves unit testing capability.

Detection Algorithm: The structural analyzer balances routine begin and matching end tokens to compute exact line spans (bodyEndLine - bodyStartLine + 1). If the body line count exceeds longMethodMaxLines (default: 60 lines), a Warning finding is generated on the routine's declaration header.

⚠️ Anti-Pattern (Monolithic Procedure > 60 lines)
procedure TOrderProcessor.ProcessOrder(const OrderId: Integer);
begin
  // 70+ lines of monolithic code handling:
  // 1. Validation
  // 2. Database transaction
  // 3. Discount calculation
  // 4. Email notification setup
  // 5. UI state update
end;
✅ Recommended Compliant Code
procedure TOrderProcessor.ProcessOrder(const OrderId: Integer);
begin
  ValidateOrder(OrderId);
  ExecuteOrderTransaction(OrderId);
  SendConfirmationEmail(OrderId);
  UpdateUIState;
end;
deepNesting Excessive Control-Flow Nesting Depth
Warning
CategoryMetrics & Complexity
Source Filesrc/engine/builtinRules/deepNesting.ts
Config Settingdelphisense.deepNesting.maxDepth (default: 4)

Description & Objective: Tracks control-flow block nesting (begin, case, if, for, while, try) within routine bodies and flags lines where nesting exceeds the threshold. Prevents "Arrow Anti-Pattern" code that is hard to read and debug.

Detection Algorithm: Iterates line-by-line through the routine body, incrementing depth on block-opening keywords (begin, case) and decrementing on end keywords. If depth > maxDepth (default: 4), a Warning finding is reported at the exact line where the threshold is breached.

⚠️ Anti-Pattern (Nesting Depth = 5)
procedure ProcessData;
begin
  if OrderId > 0 then
    for i := 1 to 10 do
      if i > 5 then
        if i mod 2 = 0 then
          begin // Nesting depth = 5!
            DoWork;
          end;
end;
✅ Recommended Guard Clause Refactoring
procedure ProcessData;
begin
  if OrderId <= 0 then Exit; // Guard Clause

  for i := 6 to 10 do
  begin
    if i mod 2 = 0 then
      DoWork;
  end;
end;
emptyExceptFinally Empty Exception Handler or Cleanup Block
Warning
CategoryStrong Warnings
Source Filesrc/engine/builtinRules/emptyExceptFinally.ts
Config Disable Key"emptyExceptFinally" in delphisense.rules.disabled

Description & Objective: Detects except...end blocks with no operational code (which silently swallow runtime errors) and empty finally...end blocks (dead cleanup blocks).

Detection Algorithm: Identifies lines starting with except or finally. Scans look-ahead lines up to the matching end statement. If no non-comment, non-blank statements exist inside the block, a Warning finding is generated.

⚠️ Anti-Pattern (Swallowed Exception)
try
  PerformDatabaseUpdate;
except
  // Exception silently swallowed — dangerous!
end;
✅ Recommended Compliant Code
try
  PerformDatabaseUpdate;
except
  on E: Exception do
    Logger.LogError('Update failed: ' + E.Message);
end;
deadCodeAfterExit Unreachable Statements After Exit / Raise / Abort
Warning
CategoryCode Reduction
Source Filesrc/engine/builtinRules/deadCodeAfterExit.ts
Config Disable Key"deadCodeAfterExit" in delphisense.rules.disabled

Description & Objective: Flags statements located directly after unconditional Exit;, Exit(...), raise ...;, or Abort; statements that can never be executed.

Detection Algorithm: Detects lines ending with unconditional control terminators. Inspects the next non-blank, non-comment line. If that line contains an operational statement (and is not a valid block closer like end, until, else, except, or finally), it flags the line as dead code.

⚠️ Anti-Pattern (Unreachable Code)
procedure ValidateUser;
begin
  Exit;
  s := 'unreachable assignment'; // Will never execute!
end;
✅ Recommended Compliant Code
procedure ValidateUser;
begin
  if not IsValid then
    Exit;
  
  s := 'valid assignment';
end;
longLine Source Line Length Threshold Exceeded
Hint
CategoryMetrics & Complexity
Source Filesrc/engine/builtinRules/longLine.ts
Config Settingdelphisense.maxLineLength.max (default: 120)

Description & Objective: Flags individual source lines whose character count exceeds the configured maximum length. Ensures code readability on side-by-side diff viewers and smaller displays.

Detection Algorithm: Checks length of raw source lines (line.length > max). If exceeded, reports a Hint finding starting at column max + 1.

todoComment Technical Debt & Action Item Annotations
Hint
CategoryCode Reduction
Source Filesrc/engine/builtinRules/todoComment.ts
Config Disable Key"todoComment" in delphisense.rules.disabled

Description & Objective: Extracts technical debt comment markers (TODO, FIXME, HACK, XXX) from code comments and surfaces them as Hints in VS Code.

Detection Algorithm: Evaluates extracted comments against regex /\b(TODO|FIXME|HACK|XXX)\b[:\s]*(.*)/i. Extracts marker text and detail description to populate the diagnostic message.

customRules Engine Declarative Workspace Pattern Rules
Custom
CategoryCustom / Security / Standards
Source Filesrc/engine/customRules.ts
Workspace Config File.delphisense/rules.json

Description & Objective: Allows development teams to declare custom, pattern-based review rules in JSON format without writing TypeScript code or modifying extension binaries.

Schema Example: 

{
  "rules": [
    {
      "id": "noHardcodedConnStr",
      "pattern": "Password\\s*=",

      "severity": "error"
    },
    {
      "id": "noShowMessageInLoop",
      "pattern": "ShowMessage\\s*\\(",
      "message": "Avoid ShowMessage in production code paths — prefer logging.",

Comprehensive Feature List

6.1. Multi-Target Analysis
  • Analyze Current File: Instant verification of the active editor file or context menu target.
  • Analyze Folder: Recursive scan of selected directory trees with automated noise folder exclusion.
  • Analyze Project (.dpr/.dpk): Smart resolution of project main files and referenced units.
  • Analyze Workspace: Full scan across open workspace folders.
6.2. VS Code UI Integrations
  • Problems Panel Integration: Live warnings, errors, and hints with line jump navigation.
  • Explorer Context Menus: Right-click options on `.pas`, `.dpr`, `.dpk`, and folders.
  • Webview Review Panel: In-editor tab showing styled quality score ring, category distribution, and findings.
  • Export Affordance: One-click "Save Report As..." export option to preserve HTML review reports.
7

Non-Functional & Architectural Strengths

  • Zero Runtime Dependencies: Uses standard Node.js built-ins (`fs`, `path`, `os`) with a package footprint of ~100 KB.
  • Decoupled Core Architecture: Pure TypeScript engine isolated from VS Code APIs for CLI wrapper capability.
  • High Throughput: Scans tens of thousands of lines of code in under 100 milliseconds.
  • 100% Offline Safe: HTML reports require zero external fonts, JS frameworks, or internet calls.

Recommended Next-Step Roadmap

  1. CLI Package Entry Point: Expose `src/engine/` via a Node CLI script for GitHub Actions & CI quality gates.
  2. Quick Fixes (CodeActions): Provide auto-fix options (e.g. remove unused `uses` item).
